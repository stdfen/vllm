# DeepSeek V4.1 EXL3 on two GB10 nodes

This experimental compatibility branch starts at upstream v0.33.0, commit
`4ba787ec9959e566d3b587a796dff07673324da5`. It is not an unmodified upstream
release. The common compatibility changes must be present in both the A and B
images; their effect is not attributed to the subsequent P0 changes.

## Common compatibility scope

- Register the checkpoint's `deepseek_v41_exl3` mixed quantization format. Retain
  the native FP8 configuration for tensors outside the EXL3 plan; routed experts
  have fractional mixed bit widths, dense projections and the head use integer K.
- Load the checkpoint's grouped output projections and packed language-model head.
- Serialize EXL3 projection streams that share native scratch and lock buffers.
- Support `--engram-config` with `disk_offload=true`, `cpu_offload=true`, and
  `dp_shared_memory=false`, reading rows from the original checkpoint files.
  `disk_threads` selects the persistent host-reader thread count (default 32).
- Limit the initial disk backend to DeepSeek V4.1 with DP1, PP1 and no EP.

The native reader is adapted from the archived S3 installed source. Its source
SHA256 before adaptation is
`91d53d241d1a73da1a1f2883cdad52ba3026789de7748224cb44d45a5f9c170d`.
The mixed-format compatibility package is ported from the previous image's
`vllm_exl3_moe` Python/CUDA sources, archive SHA256
`4ffe0dfbdd087a957fb403c86730bdafac271c3f99124bedd4e09836bf1aec2b`.
An upstream revision for that package was not recorded, so the archive identity
and this branch's commits establish its provenance. The earlier generic EXL3
draft did not describe this checkpoint and is superseded by this implementation.
The image disables optional dense mrow, SMoE, fused preparation, TensorFold prompt
kernels and L2 prefetch. The plugin's RDMA/router/mHC registration hooks are not
installed. Both A and B inherit these same common settings.
The runtime remains vLLM 0.33: scheduler, attention implementation, KV management,
and the rest of the package come from the pinned upstream release.

Use lazy safetensors loading for the disk backend. Eager or whole-checkpoint
prefetch defeats its memory-capacity objective. A single-rank whole-table UVA
reference does not fit this checkpoint on a 128 GB UMA machine; use isolated
row/kernel comparisons and the common disk baseline for whole-model regression.

## Build and verification status

The base is the official ARM64 `vllm/vllm-openai:v0.33.0`, whose platform manifest is
`sha256:e3481489818d3e563cae517b84ab959cc8b69f85a9fbb771c189140131ffc65c`.
EXL3 native sources must be rebuilt for the base image's PyTorch/CUDA ABI. Do not
copy the old S3 shared object into the new runtime.

At this commit the compatibility implementation is under development. Syntax
checks are not a claim that image building or full-model TP2 validation passed.
Release receipts must record the built image identity, exact source diff, GPU
row/projection tests, API generation/streaming/concurrency tests, and the
configuration used on both nodes.

## P0 work after A passes

The B branch adds a calibrated UMA ledger/preflight, further bounded read-path
optimizations, and physical per-rank packs with manifest verification. A manifest
that only references the original safetensors is not a physical offline pack.
No speedup is assumed. Preserve identical common inference settings for A/B and
record their functional-validation and user performance windows separately.
