# GB10 性能对照 · 原生 vLLM 0.33.0

A1/A2 为原生 vLLM 0.33.0 V2 Model Runner、DFlash2 K=7 和
`FULL_AND_PIECEWISE` CUDA Graph。B 使用相同基底加 Tree-DFlash2 K=15、
批量 GPU 状态提交、长前缀 Graph 和原 2K/C8 分桶，外层 eager。
B 的源码树为 `de1f7b4b9d33a5125ea131c69c6dc13d99d8436b`，早于本分支的
编译 prefill 和多请求通用分桶。K 值和 Graph 路径随部署方案变化。
当前源码的单变量 A–B–A 见[合入记录](integration.md)。

## 测试口径

- 同一张 GB10 串行运行，驱动 580.95.05。镜像统一使用 `vllm/vllm-openai:v0.33.0`，
  本机镜像 ID 为 `sha256:a0dfdeea1d42d4201c82d9bb44f2f4bb1ac2ef5aea196e9e0d1007a2834d2f70`。
- 共用 Qwen3.8-27B ModelOpt NVFP4/FP8、同一 DFlash2 草稿、TP1、BF16、FP8 KV、
  FP32 GDN、TRITON_ATTN、131072 上下文、最多 8 请求、8192 批 token 上限、显存比例
  0.75。采用同步调度、chunked prefill、关闭 prefix cache。
- 冻结 ShareGPT 提示包 SHA256 为
  `edb3560763e3545978d319a7d88082d1bbb35dbb6f7622bb6623c1b2e7fa4742`。
  输入 2048/8192，输出 1024，seed 11230，贪心解码，忽略 EOS。
  C1 每轮 2 条，C8 每轮 10 条，每格三轮。C1/C8 分别热身 3/8 条，每条热身输出 128。
  三臂共 216/216 正式请求通过配对、长度和服务回执检查。
- TPOT 用末次与首次有效 SSE 输出的时间差除以输出 token 数减一。输出吞吐计入客户端执行全程。
  B 相对 A1/A2 均值计算差异，漂移为两次 A 的绝对差除以该均值。绝对差异超过漂移才判为可分辨。

A1/A2 在四格预热中有原生 FULL Graph 重放日志。B 的满批 C8 验树重放为
2K 416/441、8K 254/582。两套 Graph 计数范围和草稿接受率分母不同。
B 在两格 C1 均降低约 27% 的 TPOT，2K/C8 的 TPOT 差异落在漂移内，
8K/C8 的 TPOT 与吞吐均出现可分辨退化。四格 TTFT p50 均上升。

A1/B 完成后，旧 Xid 从内核环形缓冲区滚出，触发原脚本停止。
持久内核日志在整个实验窗口内无新增 Xid，保留 A1/B 并按原合同补跑 A2。
本轮性能测试未验证逐 token 等价。
